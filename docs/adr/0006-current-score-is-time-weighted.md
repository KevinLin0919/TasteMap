# Current Score 採時間加權，不是平均值

一間 Place 的代表分數由其所有 Visit 的 Score 依時間加權推導，**半衰期 24 個月**（權重 = `0.5^(月數/24)`）。店家會換廚師、漲價、變吵，使用者的口味也會變；這個數字要回答的是「我現在該不該去」，不是「這家店歷史上有多好」。

半衰期取 24 個月而非 12，是因為使用者的使用模式偏向探索新店而非頻繁回訪同一家，造訪間隔長。12 個月會讓一年前那次衰減至 0.5、兩年前僅剩 0.25，等於每次都只憑最新一次判斷，失去累積的意義。24 個月下，一年前仍保有 0.71、兩年前 0.50。

## Considered Options

**只取最近一次**被否決：過於脆弱，單次踩雷（廚師剛好請假）就會把去過十次的愛店打入冷宮。

**平均加上次數加成**被否決：不應把「幾分」與「多確定」混為同一個數字，否則 4.5 究竟代表「很好吃」還是「去很多次」將無法分辨。造訪次數僅作為分數相同時的排序 tiebreaker，維持現行 `ranking` 的行為。

## Consequences

**這是刻意偏離顯而易見的做法。** 後續維護者看到 `averageScore` 會直覺認為它應該是算術平均並「修正」它 —— 該識別字已名不符實，應更名為 Current Score 對應的名稱。

此數字的影響面極廣：Collection 排序與入選門檻、地圖圖釘數字與徽章顏色、地圖篩選、足跡統計、搜尋排序、詳情頁大字、分享文字。變更公式等於同時改動以上全部。

`TasteMapCore` 既有測試 `averageRoundsToOneDecimal` 需一併重寫。

個別 Visit 的 Score 不受影響，永遠保留使用者當下給的原值，`PlaceDetailView` 仍完整列出每一次造訪。
